## 1. Contexto e objetivo

No v1 (Python/PyQt6, `C:\dev\Projeto Rpg\src\ui\mapa_ascii.py`) o "mapa" é um **`QTextEdit` de texto livre**: o mestre digita a grade ASCII na mão, mantém o alinhamento sozinho, e o único caminho pro Discord é o botão `copiar_mapa` → clipboard (envolve em ```` ``` ```` e o mestre cola manualmente no canal). Não há grade de verdade, nem células, nem clique, nem cor, nem sincronização. O usuário diz explicitamente: **"não consegui fazer o mapa dentro do Python"** — o Python só deu conta do texto puro.

O print de referência do usuário ("Floresta de Noite", grade A–Z × 1–7, `X` = árvore, cards escuros) é o **alvo visual** — não existe protótipo reaproveitável no repo (o `.vercel` do v1 é órfão, projeto Trae `trae_euheavav`).

**Meta do Slice 1:** um **editor de mapa ASCII de verdade** no v2 — biblioteca de mapas nomeados + grade clicável (pinta célula) + campos de texto (Título/Ordem/Legenda/Efeito) + preview ao vivo no visual do print, persistido no SQLite. Mais uma **função pura em Rust `render_discord(&Mapa) -> String`** que produz **exatamente** o bloco que o bot vai postar na Fase 4 — testável por `cargo test`, sem depender de rede nem do Discord. Enquanto o bot não existe, um botão **"Copiar pro Discord"** (clipboard, igual v1) dá valor imediato e já exercita a render.

### Decisões travadas (via grilling)

| # | Tema | Decisão | Motivo |
|---|------|---------|--------|
| 1 | Edição | **Grade clicável**: paleta de caracteres, clica na célula e pinta | Nunca desalinha (crítico pro code block do Discord), permite cor por tipo, é o upgrade que o `QTextEdit` do v1 não dava |
| 2 | Escopo | **Biblioteca de vários mapas** nomeados (criar/duplicar/apagar/trocar) | O usuário já tem mapas com nome ("Floresta de Noite"); casa com "escolher o mapa da sessão" pro Discord; caro é retrofitar depois |
| 3 | Fidelidade no Discord | **(A) Monoespaçado sem cor** no Discord; cor fica só no app | Robusto e idêntico em PC/celular; ANSI dá só ~8 cores e falha no mobile — vira opção futura, não risco agora |
| 4 | Paleta | **Fixa embutida** (`-` `X` `~` `#` `.` + qualquer letra pra ponto de interesse) + **Legenda = texto livre** por mapa | Entrega rápido; catálogo editável de terrenos é YAGNI agora |
| 5 | Composição no Discord | **Mapa inteiro**: título **negrito** + grade em ```` ``` ```` + Ordem/Legenda/Efeito como texto normal fora do bloco | É o print inteiro; texto comprido dentro de code block rola horizontal no celular (o "Efeito" longo ficaria ruim) |
| 6 | Dimensões | **Configuráveis por mapa**: colunas 6–26 (default 26 = A–Z), linhas 3–50 (default 7). Sem pular a linha 16 | Mapas de combate mais justos ficam melhores no celular; o "pula 16" do v1 era bug |
| 7 | Armazenamento da grade | **JSON texto** (array de strings, uma por linha, cada char = 1 célula) numa coluna `TEXT` | Simples, atômico, casa com o estilo do projeto (rusqlite, sem ORM); grade é pequena |
| 8 | Salvamento | **Auto-save** debounced no banco (sem botão "Salvar"); flush ao trocar de mapa | UX de biblioteca (não perde trabalho ao trocar de mapa) |
| 9 | Undo | **Undo/redo client-side** (Ctrl+Z / Ctrl+Y) na pintura da grade | Editor de pintura sem undo frustra; é barato (pilha de snapshots da grade) |
| 10 | Lugar | **Tela própria `/mapa`** (ativa o item "em breve" da sidebar); plugar dentro da Batalha vem depois | Mais fácil construir e testar isolado; o módulo é auto-contido pra embutir na Batalha na Fase 4+ |

## 2. Arquitetura e princípios

- **Separar I/O de lógica pura** (regra do usuário): o `render_discord` e a normalização da grade são **funções puras em `domain/mapa/`** — não tocam DB, disco nem UI, e são cobertas por `cargo test`. A persistência mora em `db/` (repositório com rusqlite, padrão do projeto). A UI mora em `src/features/mapa/` (React, padrão de `features/batalha/`).
- **Camadas claras** (UI → comando Tauri → repositório → SQLite): a tela nunca fala SQL; o comando nunca desenha. Igual ao que já existe pra Fichas e Batalha.
- **A grade é a fonte da verdade** do desenho. O preview no app e a render pro Discord são **derivações** da mesma grade — nunca duas verdades. Isso garante que "o que você vê no app" e "o que vai pro Discord" são o mesmo dado.
- **Render pronta pro sync, sync fora do escopo:** `render_discord` é entregue e testada agora; a Fase 4 só a chama (bot posta/edita). Nenhum acoplamento com rede neste slice.
- **Consistência com o projeto:** nomes de coluna em snake_case pt-BR, `criado_em`/`atualizado_em` como em `personagem`/`imagem`, DTOs em `domain/modelos.rs`/módulo próprio, bindings espelhados em `src/lib/api.ts` e tipos em `src/lib/types.ts`.

## 4. Modelo de domínio (Rust)

```rust
// domain/mapa/modelos.rs

/// Um mapa ASCII completo. `grade` já normalizada: exatamente `linhas`
/// strings, cada uma com exatamente `colunas` chars (1 char = 1 célula).
struct Mapa {
    id: i64,
    titulo: String,
    colunas: u8,            // 6..=26
    linhas: u8,             // 3..=50
    grade: Vec<String>,     // len == linhas; cada String.chars().count() == colunas
    ordem_navegacao: String,
    legenda: String,
    efeito: String,
    criado_em: String,
    atualizado_em: String,
}

/// Resumo pra lista lateral (não carrega a grade).
struct MapaResumo {
    id: i64,
    titulo: String,
    atualizado_em: String,
}

/// Entrada de criação/atualização vinda da UI.
struct MapaInput {
    titulo: String,
    colunas: u8,
    linhas: u8,
    grade: Vec<String>,     // será normalizado (pad/crop) pra colunas×linhas
    ordem_navegacao: String,
    legenda: String,
    efeito: String,
}

const CELULA_VAZIA: char = '-';
const COLUNAS_MIN: u8 = 6;  const COLUNAS_MAX: u8 = 26;   // A..Z
const LINHAS_MIN: u8 = 3;   const LINHAS_MAX: u8 = 50;
const LIMITE_DISCORD: usize = 2000;
```

**Normalização (pura, `domain/mapa/modelos.rs`):**

```rust
/// Garante colunas/linhas dentro dos limites e a grade com formato exato:
/// - clampa colunas em [6,26] e linhas em [3,50];
/// - cada linha existente é cortada ou preenchida com CELULA_VAZIA até `colunas`;
/// - adiciona/remove linhas até `linhas` (novas = tudo CELULA_VAZIA);
/// - qualquer char de controle/whitespace numa célula vira CELULA_VAZIA.
fn normalizar(input: MapaInput) -> MapaInput
```

Chamada em `criar_mapa` e `atualizar_mapa` (antes de gravar) e no `get_mapa` (defensivo ao ler, caso o JSON no banco esteja inconsistente). A UI também mantém o formato, mas o domínio é a garantia.

## 5. Schema (migration `0003_mapa.sql`)

Segue as convenções de `0001_init.sql` (id inteiro, snake_case, timestamps `datetime('now')`, `TEXT NOT NULL DEFAULT ''`).

```sql
CREATE TABLE mapa (
    id               INTEGER PRIMARY KEY,
    titulo           TEXT NOT NULL DEFAULT '',
    colunas          INTEGER NOT NULL DEFAULT 26,
    linhas           INTEGER NOT NULL DEFAULT 7,
    grade            TEXT NOT NULL DEFAULT '[]',   -- JSON: array de strings (uma por linha)
    ordem_navegacao  TEXT NOT NULL DEFAULT '',     -- campo "Ordem" do print (nome do v1)
    legenda          TEXT NOT NULL DEFAULT '',
    efeito           TEXT NOT NULL DEFAULT '',
    criado_em        TEXT NOT NULL DEFAULT (datetime('now')),
    atualizado_em    TEXT NOT NULL DEFAULT (datetime('now'))
);
```

- `grade` é o JSON de `Vec<String>` (serde_json). Escrita/leitura via `serde_json::to_string`/`from_str` no repositório.
- `ordem_navegacao` evita colisão com a convenção de coluna-de-ordenação `ordem` usada nas tabelas-filho do v2; e é o mesmo nome de chave do v1 (`ordem_navegacao`).
- Sem FK — mapa é independente de personagem/batalha neste slice.
- `atualizado_em` é reescrito em cada `atualizar_mapa` (o repositório seta `datetime('now')`).

## 6. Comandos Tauri + API TS

Registrados em `src-tauri/src/lib.rs` (padrão dos 26 comandos já existentes) e espelhados em `src/lib/api.ts` + tipos em `src/lib/types.ts`.

| Comando | Assinatura (Rust) | Uso |
|---------|-------------------|-----|
| `listar_mapas` | `() -> Vec<MapaResumo>` | popular a lista lateral (ordenado por `atualizado_em` desc) |
| `get_mapa` | `(id: i64) -> Mapa` | abrir um mapa no editor (grade normalizada na leitura) |
| `criar_mapa` | `(input: MapaInput) -> Mapa` | novo mapa (título default "Novo mapa"); normaliza; retorna com id |
| `atualizar_mapa` | `(id: i64, input: MapaInput) -> Mapa` | salvar edições (auto-save); normaliza; seta `atualizado_em` |
| `duplicar_mapa` | `(id: i64) -> Mapa` | copia tudo, título + " (cópia)", novo id |
| `excluir_mapa` | `(id: i64) -> ()` | apagar da lista |
| `render_mapa_discord` | `(input: MapaInput) -> String` | gera a string do Discord a partir do **estado atual do editor** (fonte única pro botão "Copiar" e, na Fase 4, pro bot) |

Erros via `AppError` (padrão do projeto, `db/error.rs`). Todos os comandos são finos: validam via `normalizar` e delegam ao repositório `db/repositorios.rs` (funções `mapa_*`). O `render_mapa_discord` normaliza o input, monta um `Mapa` transitório e chama `domain::mapa::render::render_discord` (a render nunca é reimplementada no cliente).

## 7. Render pro Discord (função pura, testável)

```rust
// domain/mapa/render.rs
fn render_discord(m: &Mapa) -> String
fn excede_discord(s: &str) -> bool   // s.chars().count() > LIMITE_DISCORD
```

**Formato exato produzido (sem ambiguidade):**

1. Se `titulo` não vazio: linha `**{titulo}**` seguida de uma linha em branco.
2. **Bloco de código** (cerca ```` ``` ````) contendo a grade:
   - `largura_rotulo = número de dígitos de linhas` (ex.: 7→1, 20→2).
   - **Linha de cabeçalho:** `largura_rotulo + 1` espaços, depois as letras de coluna `A B C …` (só as `colunas` primeiras de A–Z), separadas por 1 espaço.
   - **Cada linha i (1-based):** `str(i)` alinhado à direita em `largura_rotulo`, um espaço, depois as `colunas` células separadas por 1 espaço. Célula vazia = `-`.
3. Fora do bloco, uma linha em branco e então, **apenas para os que não estão vazios**:
   - `**Ordem:** {ordem_navegacao}`
   - `**Legenda:** {legenda}`
   - `**Efeito:** {efeito}`

**Exemplo** (grade 8×3 ilustrativa — o formato exato; cabeçalho com 2 espaços de recuo pra `largura_rotulo=1`):

````text
**Floresta de Noite**

```
  A B C D E F G H
1 - X X - - - - -
2 - - - X - - - -
3 - - - - X X - -
```

**Ordem:**  ->  ->
**Legenda:** X → Árvores
**Efeito:** Terreno de Noite, se oponente tiver mais de 5 blocos de distância...
````

- **Guard 2000:** `render_discord` **não trunca**; a UI (e, na Fase 4, o comando de sync) usa `excede_discord` pra avisar "passa de 2000, o Discord vai cortar". Discord conta ~code points; `chars().count()` é o proxy.
- **Sem cor:** decisão 3. Uma futura `render_discord_ansi` (Fase 4+) embrulharia a grade em ```` ```ansi ```` com códigos de cor — porta aberta, fora do escopo.

## 8. UI / Tela `/mapa`

Layout (padrão de duas/três colunas do projeto, Tailwind v4, tema escuro):

```
┌─────────────┬──────────────────────────────────────────────┐
│  MAPAS      │  EDITOR                     │  PREVIEW         │
│  ┌────────┐ │  Título: [Floresta de Noite]│  **Floresta...** │
│ >│Floresta│ │  Colunas [26] Linhas [7]    │  ┌────────────┐  │
│  │Caverna │ │  Paleta: [-][X][~][#][.][A] │  │  A B C ...  │  │
│  │Vila    │ │  ┌───────────────────────┐  │  │1 - X X ...  │  │
│  └────────┘ │  │  grade clicável A–Z×N │  │  └────────────┘  │
│  [+ novo]   │  └───────────────────────┘  │  Ordem: ...      │
│             │  Ordem   [texto............]│  Legenda: ...    │
│             │  Legenda [texto............]│  Efeito: ...     │
│             │  Efeito  [texto............]│  [Copiar Discord]│
└─────────────┴──────────────────────────────────────────────┘
```

- **Lista lateral:** `listar_mapas`; selecionar → `get_mapa`. Botões: `+ novo` (`criar_mapa`), duplicar e apagar (com confirmação) por item.
- **Grade clicável:** grid CSS de `colunas × linhas`. Célula = botão/`<div>` monoespaçado. **Caractere ativo** vem da paleta (ou de um input "letra" pra ponto de interesse). Clique pinta a célula com o caractere ativo; **arrastar** pinta contínuo (mousedown+enter). Cor por tipo via classe (`-` apagado, `X` verde, `~` azul, `#` cinza, `.` bege, letras = destaque).
- **Paleta fixa:** `- X ~ # .` + campo pra digitar 1 letra/dígito (ponto de interesse). Botão "borracha" = pintar `-`.
- **Dimensões:** inputs numéricos (clamp 6–26 / 3–50). Mudar preserva células existentes (pad/crop via a mesma lógica de `normalizar`, aplicada no cliente pra resposta imediata; o backend re-normaliza ao salvar).
- **Campos de texto:** Título, Ordem, Legenda, Efeito (`<input>`/`<textarea>`).
- **Preview ao vivo:** deriva da mesma grade/campos, no visual do print (cards escuros arredondados, fonte monoespaçada, cor por tipo). É o "espelho no app" do que o Discord vai receber (menos a cor).
- **Auto-save:** qualquer edição agenda `atualizar_mapa` com debounce ~500ms; trocar de mapa/fechar dá flush. Indicador discreto "salvo".
- **Undo/redo:** pilha client-side de snapshots da grade (e das dimensões); Ctrl+Z / Ctrl+Y. Cobre a pintura e o resize; os campos de texto usam o undo nativo do input.
- **Copiar pro Discord:** chama o comando `render_mapa_discord(input)` (Rust — fonte única e testada) com o estado atual do editor e escreve o resultado no clipboard. Se `excede_discord`, mostra aviso "passa de 2000, o Discord corta".
- **Navegação:** `src/App.tsx` ganha `<Route path="/mapa" element={<MapaScreen/>}/>`; `src/components/Sidebar.tsx` dá `to: "/mapa"` ao item `mapa` (hoje sem `to`, cai no ramo "em breve" — `Sidebar.tsx:26` e render desabilitado `:65-81`).

> Observação: a render que vai pro Discord é **sempre** a do Rust (`render_discord`), fonte única. O preview do app pode reusar a mesma string dentro de um `<pre>` (garante paridade visual exata com o Discord) ou ter um render React próprio mais bonito — **decisão de implementação a fechar no plano**; a recomendação é o preview React bonito + um "ver como fica no Discord" que mostra a string crua de `render_discord`.

## 10. Testes e verificação

**`cargo test` (puros, deterministas):**
- **`normalizar`:** grade menor que colunas → pad com `-`; maior → crop; linhas a mais/menos → ajusta; char inválido (espaço/controle) → `-`; clamp de colunas (5→6, 30→26) e linhas (2→3, 99→50).
- **`render_discord`:** cabeçalho alinha com as células; `largura_rotulo` correto pra 7 (1 dígito) e pra 20 (2 dígitos); célula vazia sai `-`; título vazio omite a linha; Ordem/Legenda/Efeito vazios são omitidos, preenchidos aparecem com o rótulo em negrito; grade dentro do bloco ```` ``` ````, textos fora.
- **`excede_discord`:** mapa 26×50 cheio + textos longos → `true`; mapa pequeno → `false`; contagem por `chars()` (com acento) correta.
- **round-trip de serialização** da grade (Vec<String> ↔ JSON) preserva o conteúdo.

**Verificação manual (no app, padrão "testar UI no browser" do usuário):**
- Criar mapa, pintar a "Floresta de Noite" do print, ver o preview bater com o print.
- Trocar de mapa e voltar: edições persistiram (auto-save).
- Duplicar e apagar funcionam; lista atualiza.
- Redimensionar preserva o desenho.
- Undo/redo desfaz/refaz pintura.
- "Copiar pro Discord" → colar num canal → alinhamento perfeito no PC; aviso aparece quando estoura 2000.

## 12. Riscos e mitigações

| Risco | Mitigação |
|-------|-----------|
| Mapa largo estoura os 2000 do Discord | `excede_discord` avisa; colunas configuráveis pra baixo (6–26); Ordem/Legenda/Efeito fora do bloco (não inflam tanto) |
| Alinhamento quebra no celular (code block rola horizontal) | Decisão 6: incentivar mapas mais estreitos; 1 char + 1 espaço por célula mantém legível; sem cor (decisão 3) evita ANSI quebrado no mobile |
| Auto-save disparar demais / corrida ao trocar de mapa | Debounce ~500ms + flush explícito na troca; `atualizar_mapa` é idempotente |
| Grade no banco inconsistente (edição manual, bug) | `normalizar` defensivo também na leitura (`get_mapa`) |
| Divergência app-vs-Discord | Fonte única `render_discord`; preview deriva/espelha a mesma string |
| Escopo vazar pra tokens/tático | §3 FORA explícito: mapa é terreno ASCII; movimento de combatente é outra fase |
| Sem git no repo (não dá pra commitar a spec) | Escrever o arquivo; combinar com o usuário se quer `git init` antes de seguir |
